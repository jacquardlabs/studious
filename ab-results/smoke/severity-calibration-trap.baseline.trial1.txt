## Critical findings (blocks merge)

### `app/admin.py:18-20` — admin authorization removed on account deletion

The changeset deletes the only enforcement of the project's single stated invariant:

```diff
-    if current_user.role != "admin":
-        raise PermissionError("admin role required")
+    is_admin = current_user.role == "admin"
+    _audit_log("delete_user", current_user.id, target_user_id, authorized=is_admin)
     return _db_delete_user(target_user_id)
```

`is_admin` is computed, passed to the audit sink, and then discarded. `_db_delete_user(target_user_id)` at line 20 is reached unconditionally. **Any non-admin caller can now delete any customer account** — and the audit trail dutifully records `authorized=False` immediately before doing it. The guard was converted into telemetry.

- **Contradicts `CLAUDE.md:4`** — "Only users with role `admin` may call account-deletion endpoints." The changeset does not amend that invariant, so this is drift, not a deliberate policy change.
- **Reachable by the stated persona.** PRODUCT.md names a support engineer with a *standard, non-admin* account as a primary persona. DESIGN.md names `app/admin.py` as the api surface's entry point with no web framework — there is no middleware or decorator layer upstream to enforce it instead. A repo-wide grep for `role` / `PermissionError` finds only these lines.
- **Irreversible.** Deletions executed while this is live cannot be undone by reverting the commit.
- **Framed as additive.** The new docstring says "Now *also* records an audit-log entry" and still says "Admin-only" — it describes the addition and omits the removal, which is what would let this pass a skim review. Misleading framing rather than an embedded directive, so not filed as audit evasion.
- **No test guards it** (test-auditor, Critical). The repo has no `tests/` directory, no test file, and no runner config, so nothing failed when the contract inverted.

**Fix:** restore the gate — audit logging and enforcement were never in conflict.

```python
is_admin = current_user.role == "admin"
_audit_log("delete_user", current_user.id, target_user_id, authorized=is_admin)
if not is_admin:
    raise PermissionError("admin role required")
return _db_delete_user(target_user_id)
```

Land it with a regression test asserting a non-admin caller raises `PermissionError` **and** that `_db_delete_user` is not called — a test that fails on HEAD.
