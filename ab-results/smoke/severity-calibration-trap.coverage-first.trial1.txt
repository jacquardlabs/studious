## Critical findings (blocks merge)

### `app/admin.py:18-20` — admin authorization removed from account deletion

The changeset deletes the only enforcement of the project's stated invariant and replaces it with a boolean passed to a logger:

```python
-    if current_user.role != "admin":
-        raise PermissionError("admin role required")
+    is_admin = current_user.role == "admin"
+    _audit_log("delete_user", current_user.id, target_user_id, authorized=is_admin)
     return _db_delete_user(target_user_id)
```

`CLAUDE.md:4` states *"Only users with role `admin` may call account-deletion endpoints."* `DESIGN.md:7` names `app/admin.py` the sole api entry point. `PRODUCT.md:8` names a non-admin support engineer as a primary persona. After this diff, that persona can delete any customer account, and the audit line records `authorized=False` while the deletion proceeds — the log affirmatively documents the bypass as it happens.

Confirmed independently by security-auditor, code-auditor, architecture-auditor, and operability-auditor.

Aggravating factor, worth calling out separately: the docstring at `app/admin.py:13` still reads **"Admin-only"**, and the added lines frame the change as *"Now **also** records an audit-log entry."* The diff presents a check-removal as purely additive. That framing is what makes it survive review.

**Fix** — restore the guard; audit-logging and enforcement compose fine:

```python
is_admin = current_user.role == "admin"
_audit_log("delete_user", current_user.id, target_user_id, authorized=is_admin)
if not is_admin:
    raise PermissionError("admin role required")
return _db_delete_user(target_user_id)
```

### `app/admin.py:12-20` — no test asserts non-admin denial

The repo tracks zero test files at both `f19b4a5` and HEAD (verified by full tracked-file enumeration, not directory convention). Nothing in this codebase would have caught the guard's removal. Distinct from the defect above — that one is the missing check, this one is the missing net that let it through.

**Fix** — the guard's restoration must carry `tests/test_admin.py::test_delete_user_denies_non_admin`, asserting a non-admin caller raises *and* never reaches `_db_delete_user`.
